# 인계 및 검증 기록

정리일: 2026-11-26. 현재 상태는 **시운전 예제 / 전체 수용 검증 미완료**다.

## 확인한 사항

- 빈 장면의 신규 부품으로 스태커 크레인, 9×6 랙, 입출고 라인, 센서, 시작·리셋 버튼을 구성했다.
- Factory I/O 2.5.10의 Modbus TCP/IP Server와 PyModbus 3.11.1 `device_id=1`로 통신했다.
- 입고 센서 감지, Load in 정지, 좌측 인수, 리프트 상승, 포크 중앙 회수를 실제 장면에서 확인했다.
- `controller.py`로 1번 칸 적재 → 99번 복귀 → DONE을 확인했다. 화면에서도 우측 아래 첫 칸의 팔레트 안착을 확인했다.
- 30개 S 좌표, 생성 횟수, 시작 재누름, 이동 시작 신호 누락, Reset, 주행 인터록은 모형 기반 테스트로 확인했다. 모형 테스트는 실제 30개 안착 검증을 대신하지 않는다.

## 남은 문제

1. 시작 버튼의 마우스 누름이 DI 6에 전달되는지 확인하지 못했다. 근접 카메라를 추가했지만 UI 자동화 클릭으로 운전을 시작하지 못했다. 버튼 방향·누름 면·시뮬레이터 마우스 입력을 재점검해야 한다.
2. 조작반 배치·버튼 색상과 라벨은 추가 시각 정리가 필요하다. 현재 버튼 색상을 녹색/빨강으로 보장하지 않는다.
3. 상단 및 좌측 끝단을 포함한 S 30개 전체 적재, 인접 팔레트 간섭, 반복 공급의 장기 안정성은 미검증이다.
4. 실제 장면에서 Reset과 통신 단절의 각 동작 단계별 반응은 추가 검증이 필요하다.

마지막 전체 실행 로그 `20261125-131029-615800.jsonl`은 `IDLE / completed=0`에서 대기하다가 통신 오류 `WinError 10053`으로 FAULT 종료됐다. 전체 운전 성공 기록으로 취급하면 안 된다.

## 이번 정리에서 수정한 사항

- 장면 기본 카메라를 전체 보기로 복원하고 Overview / Controls 카메라를 보존했다.
- 노트북과 설명서의 미확인 버튼 색상 설명을 제거했다.
- 시운전 코드에서 Target=0을 정지로 사용하는 잘못된 처리를 제거했다. 중단 시 공급·이송만 끄고 크레인 상태는 유지한다. 진행 중인 크레인은 Factory I/O Pause로 멈춘다.
- Target Position에 소수·문자열·불리언이 들어가 정수로 조용히 변환되는 것을 막았다.
- 리프트 이동 시작 확인과 Reset 감시를 시운전 코드에도 반영했다.
- 장면 생성용 자체 템플릿을 프로젝트 안에 보관했다. 다른 PC의 My Scenes 경로에 의존하지 않는다.

## 다시 시작할 때

1. 기본 장면을 새로 열고 서버 IP와 Driver Start를 확인한다.
2. Controls 카메라에서 버튼 입력을 먼저 확인한다. 일반 운전은 Start 입력을 사용한다.
3. 빈 장면에서 1번·54번·상단 인접 칸을 순서대로 시운전한다. 시험마다 장면을 초기화한다.
4. 빈 장면에서 30개 전체 운전 후 로그의 30회 CYCLE_DONE, 최종 DONE 및 화면의 S 안착을 함께 확인한다.

실제 프로젝트 파일은 이번 정리에서 변경하지 않았다.

## 정리 후 파일 검증

- 자동 테스트 **8개 통과**.
- 노트북 형식 검증 및 모든 코드 셀 문법 검사 통과.
- 제어기·시운전·장면 생성 스크립트 문법 검사 통과.
- 별도 임시 폴더에서 자체 템플릿으로 장면 재생성 성공. 현재 파일과 재생성 파일 모두 부품 14개, 유효 매핑 18개, 전체 보기 기본 카메라 확인.
- 이번 정리에서는 시뮬레이터를 다시 운전하지 않았다. 실제 안착 검증 범위는 위 기록과 동일하다.
